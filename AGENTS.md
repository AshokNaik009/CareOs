# Project guidance

- Rafeeq uses React 19/Vite 6 and a CommonJS Node HTTP server. The isolated `/live-health` module uses Express/Helmet and `.mjs` server modules; do not convert the rest of the backend to ESM.
- `npm test` runs agent configuration, booking-flow/API and Live Health analysis, normalization, OAuth/API and Bluetooth controller tests. `npm run test:e2e` builds the frontend and runs Chromium tests with `.devin/playwright.config.cjs`, starting an isolated server on port 3100 with AI, WHOOP and Twilio credentials and outreach destinations disabled. Use Node 22.12+ for the test toolchain; install Chromium with `npx playwright install chromium` if needed.
- `npm run build` builds all five pages, including privacy and Live Health. `npm run serve` serves the existing build. `npm run dev` runs Node on port 3000 and Vite on 5173. For Live Health hot reload, use `APP_ORIGIN=http://localhost:5173 npm run dev`; the browser origin must exactly match APP_ORIGIN.
- Live Health uses `/live-health/api/*` and `/live-health/auth/*`. Its WHOOP callback is `APP_ORIGIN/live-health/auth/whoop/callback`. Keep its cookie, sessions, cached health data and APIs separate from demo state, demo reset, SSE, and AI providers.
- WHOOP_CLIENT_ID and WHOOP_CLIENT_SECRET stay in the server environment. Never copy secrets into examples, frontend code or tests. Production requires NODE_ENV=production and an HTTPS APP_ORIGIN; the existing demo endpoints still need access controls before public deployment.
- Preserve the WHOOP analysis semantics and methodology in `web/src/live-health/Methodology.jsx`. Unknown readings/trends stay null. No user-facing synthetic readings, except the opt-in sample mode (`LIVE_HEALTH_SAMPLE_DATA=true`, off by default, `lib/live-health/sample.mjs`): it must stay clearly labelled, never mix with real WHOOP data, and never reach alerts or calls. Other fixtures belong only in tests. Bluetooth is browser-only and does not feed resting HR, HRV, recovery or health flags.
- Reuse the shared CareOs design and navigation. Scope Live Health styles with `lh-` classes to avoid changing the patient/provider demos. Do not import voice-session hooks into Live Health.
- Live Health contact alerts are session-only and use `lib/live-health/alerts.mjs`, separate from demo AI. Supported WHOOP alerts are resting HR, SpO2, respiratory rate, and recovery; never enable blood-pressure or arrhythmia tiles without a supported data source. Alert evaluation uses fresh scored main-sleep data measured after opt-in, signed webhooks, and a five-minute reconciliation check. No Bluetooth readings enter this flow.
- Live Health calls use Twilio Programmable Voice directly, with a dedicated ElevenLabs agent for two-way conversation. Enable only after consent and setup: `TWILIO_CALLS_ENABLED=true`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM_NUMBER`, comma-separated `TWILIO_ALLOWED_NUMBERS`, `LIVE_HEALTH_ELEVENLABS_API_KEY`, `LIVE_HEALTH_ELEVENLABS_AGENT_ID`, and public HTTPS `APP_ORIGIN`. Keep calls disabled and these credentials empty during verification. Never make real test calls without explicit confirmation. The dedicated voice key does not provision demo agents; never use a demo agent or its tools for health alerts.
- WHOOP alerts add `read:profile` for authenticated account-ID matching. `/live-health/webhooks/whoop` verifies the raw JSON signature. `/live-health/webhooks/twilio/status` and `/live-health/webhooks/twilio/voice` verify URL-encoded callbacks using `X-Twilio-Signature`, the public `APP_ORIGIN` plus original path/query, and `TWILIO_AUTH_TOKEN`. Twilio callback URLs are supplied per call. No separate webhook key is needed. Health context is sent to ElevenLabs only after the contact presses 1; name confirmation is then required by the agent prompt. Enable prompt/first-message overrides, review retention, and attach no demo-action tools. Twilio recording is disabled; calls are capped at 180 seconds. Voice handoffs are single-use and expire after 10 minutes.
- Alert preferences end with the 24-hour in-memory session; persistent encrypted storage and durable jobs are required before offering always-on monitoring. Dedupe/cooldown identifiers are kept in memory for at most 48 hours, with at most one call attempt per WHOOP account per 24 hours and no automatic redial after failure.
- Starting the server with an ElevenLabs key provisions remote resources. For isolated verification explicitly set ELEVENLABS_API_KEY, GROQ_API_KEY, OPENROUTER_API_KEY, WHOOP_CLIENT_ID and WHOOP_CLIENT_SECRET to empty strings. Never run the remote-resource cleanup script as a verification step.
